## Project

PostgreSQL 16 (`postgres:16-alpine`) with pgvector v0.8.2 compiled from source
(`Dockerfile`) and `pg_stat_statements` preloaded, `wal_level=logical` enabled
for Debezium CDC, plus a pinned pgAdmin 8.10 companion. Ports
`127.0.0.1:5432` (DB) and `127.0.0.1:8080` (pgAdmin), **loopback only**. Full
spec: the canonical note in the sca-docs vault ([infrastructure catalog](https://github.com/sca-node-template/sca-docs/blob/main/04-infrastructure/INDEX.md)).

## Layout

- `compose.yml` — `postgres` (build) + `pgadmin` (`dpage/pgadmin4:8.10` pinned).
- `Dockerfile` — `postgres:16-alpine` + pgvector v0.8.2 (multi-stage build).
- `initdb/` — `01-init-extensions.sql` (`vector`), `02-pg-stat-statements.sql`,
  `03-debezium-user.sql` (role `debezium`, `REPLICATION LOGIN`); first init only.
- `Makefile` — targets: `help setup vault-secrets env up all down stop restart
  logs ps validate snapshot restore clean` (idempotent).
- `scripts/` — `vault-secrets.sh`, `gen-env.sh`.
- `.env.example` — non-secret vars and ports; `.env` is generated, gitignored.
- `.github/` — CI (`validate.yml`), PR template, CONTRIBUTING, dependabot.
- `.mcp.json` + `.claude/` — Claude Code + codegraph MCP wiring.
- `.claude/skills/` — shared AI skills (`postgres-lifecycle`,
  `postgres-snapshots`, `secrets-vault-sync`); registered for opencode via
  `opencode.jsonc` (`skills.paths`), so every agent uses the same files.
- `opencode.jsonc` + `.opencode/` — opencode project config, MCP and
  `/validate`, `/up`, `/down`, `/ps` commands.
- `docs/` — conceptual docs (architecture); operational content and
  troubleshooting live in `README.md`.
- `0.Project_info/` — user tooling (commit/merge/prompt flows); do not touch.

## Commands

- `make help` — all targets.
- `make setup` — `vault-secrets` + `env`.
- `make up` / `make all` — compose up (`-d --build`).
- `make validate` — `docker compose config --quiet` + `docker inspect` health of
  `postgres-app-db` and `postgres-app-pgadmin`.
- `make snapshot` / `make restore` — `pg_dump` into `backups/` / restore.
- `make down stop restart logs ps clean` — stack lifecycle.
- CI mirrors the static checks in `.github/workflows/validate.yml`.

## Conventions

- The compose file is `compose.yml`, not `docker-compose.yml`.
- Shell scripts: `set -euo pipefail` + a header comment only; no other comments.
- `.env` is gitignored and generated by `scripts/gen-env.sh` from Vault
  `secret/postgres-app/dev` (`DATABASE_URL`, `DB_SSLMODE`), `chmod 600`.
  Never commit `.env` or secrets. AppRole `role_id`/`secret_id` live in
  `.secrets/` (gitignored).
- Source of truth: `.env` holds `POSTGRES_USER` / `POSTGRES_PASSWORD` /
  `POSTGRES_DB`; `scripts/vault-secrets.sh` mirrors `DATABASE_URL` into Vault
  `secret/postgres-app/dev` and registers the `postgres-app` AppRole
  (read-only policy on `secret/data/postgres-app/*`). `scripts/gen-env.sh`
  preserves any existing `PGADMIN_*` values.
- Networks: `postgres` and `pgadmin` share the internal **`db_network`**
  (bridge); `postgres` also joins the external **`kafka-network`**, so Kafka
  Connect (Debezium CDC) and the `postgres-exporter` reach it by name as
  `postgres-app-db:5432`. All published ports bind to **loopback only**
  (`127.0.0.1:${POSTGRES_PORT}` / `127.0.0.1:${PGADMIN_PORT}`).
- Debezium CDC dependency: `wal_level=logical` (compose `command`) plus the
  `debezium` role (`REPLICATION LOGIN`, `SELECT` on `public`) from
  `initdb/03-debezium-user.sql`. `initdb/` runs only on first init — recreate
  the volume to re-run. Never touch the running `kafka/` stack.
- Observability: the `prometheus/` `postgres-exporter` scrapes
  `postgres-app-db:5432`; `pg_stat_statements` is preloaded and tracked
  (`track=all`) for query metrics.
- Content in English; changes land through a PR.
